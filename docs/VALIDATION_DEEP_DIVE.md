# Scientific Validation Deep Dive

The right question is not whether the model produces attractive plots. The right question is which outputs are benchmark-backed, which are only directional, and where the current validation boundary stops.

This repository now makes that separation explicit.

## 1. What counts as proof today

The strongest evidence in-repo is the free-precursor benchmark set. These are literature systems where the engine predicts named, measurable compounds and we compare them directly against reported concentrations.

The benchmark contract currently asks for:

- matched literature compounds rather than proxy classes alone
- full compound coverage for the benchmarked targets
- quantitative agreement within a strict 1.5x ratio envelope for strict-ready release claims
- ranking metrics only when at least three matched compounds make correlation meaningful

At the moment, the validated free-precursor surface includes four strict-ready benchmarks and nine matched compounds across those systems. The repository-level summary is regenerated in [results/validation/validation_overview.md](results/validation/validation_overview.md) and the detailed table lives in [results/validation/benchmark_summary.md](results/validation/benchmark_summary.md).

## 2. How to read the benchmark figures

The per-benchmark figure generated by [scripts/compare_sim_to_lit.py](scripts/compare_sim_to_lit.py) now has three parts:

- a parity plot on log scales showing predicted vs. measured concentration
- an absolute-yield panel showing the measured and predicted ppb values for each matched compound
- a compact benchmark summary panel with coverage, Pearson $R$ when valid, MAE, max ratio, overall status, and strict-ready state

The parity plot is the key scientific panel. If points sit near the 1:1 line and remain inside the shaded 1.5x band, the model is reproducing the literature concentration scale for that benchmark instead of merely getting the ordering right.

We deliberately removed the old fold-error-by-compound panel from the main figure because it added visual clutter without improving interpretability for a first-pass scientific review.

## 3. What does not count as proof yet

Plant-matrix benchmarks are currently useful intake and readiness checks, not authoritative quantitative release claims.

That distinction matters because a matrix prediction is affected by additional assumptions that are not fully benchmark-closed yet:

- precursor accessibility in peptide-bound or intact-protein systems
- headspace partitioning and pH-dependent release across real matrices
- compound-specific retention and matrix-state effects under extrusion or pre-processing history

The matrix benchmarks in the repository are still valuable because they prove the workflow is executable and because they surface calibration provenance, but they do not yet justify the same trust claim as the free-precursor literature set.

## 4. Why Pearson $R$ is not enough by itself

Correlation is useful, but it is not a sufficient scientific contract.

Two common failure modes are:

- a model gets the rank order right but misses concentration scale badly
- a benchmark has only two matched compounds, where Pearson $R$ becomes mathematically uninformative

For that reason, the repository treats these quantities differently:

- coverage tells you whether the expected compounds were found at all
- Pearson $R$ is shown only when there are at least three matched compounds
- MAE reports the average absolute concentration miss in ppb
- max ratio is the main release-facing quantitative tolerance check

This is why a benchmark can be marked `pass-no-ranking` and still be scientifically acceptable for a narrow quantitative contract.

## 5. Why the software is useful even inside a narrow envelope

Within the validated envelope, the library is already operationally useful for three scientist-facing jobs:

- screening precursor combinations before wet-lab work
- comparing the effect of pH, temperature, water activity, and reaction time on likely flavor outputs
- optimizing formulations against desirable, adverse, and safety tags while preserving a confidence story in the generated reports

Outside that envelope, the output is still useful as a directional hypothesis generator, but it should be treated as prioritization support rather than as a release-grade quantitative prediction.

## 6. What guards the model against silent drift

Validation is not a single figure. The repository also maintains regression and contract checks around:

- benchmark coverage and benchmark ratios
- matrix ranking assertions and readiness surfaces
- thermodynamic gating and pathway-projection audits
- physical invariants such as sane temperature and pH behavior in the supported modeling layers

Those artifacts are regenerated in Docker so the claimed validation state is tied to the same environment used for scientific verification.

## 7. Practical trust rule for users

Use the software in one of these three modes:

- quantitative mode: free-precursor systems that resemble the strict-ready benchmarks
- directional mode: pea/soy matrix exploration where you want likely winners, caveats, and next experiments
- exploratory mode: systems beyond the current benchmark family, where the output is hypothesis generation only

If you need a single operational summary, use this one: trust the model most when it is interpolating inside benchmark-backed free-precursor chemistry, trust it conditionally when matrix corrections dominate, and do not treat unbenchmarked matrix or extrusion-heavy outputs as release-grade quantitative evidence.
